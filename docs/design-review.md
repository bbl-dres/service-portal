# Design Review — Alignment to the Swiss Federal Corporate Design (CD Bund)

_Senior design-systems & UX review of the BBL Kundenportal prototype against the official `designsystem` repo. Method: 16 CD-expert passes (one per dimension) diffing our vanilla JS/CSS system against the official Tailwind/PostCSS CD — philosophy, BEM naming, tokens, structure and accessibility — each returning concrete, **vanilla-portable** recommendations. We stay vanilla JS + hand-written CSS, so the goal is to mirror the CD's *names, tokens, structure and intent* as closely as possible without adopting Tailwind._

## Verdict

The portal is **already well-aligned** — every dimension scored *strong* or *partial*, none *weak*. The brand-ramp/skin architecture, the CD components we reused (tabs, pagination, search header, catbar), Noto Sans, and the purple focus ring all match. The gaps are breadth and rigour, not direction: **134 findings (13 high · 45 medium · 76 low)**, and **89 are small-effort**. Four themes dominate:

1. **An incomplete token layer** — no motion tokens (durations/easings are hardcoded), only 4 of CD's 8 accent hues, no z-index scale, a truncated radius/shadow scale. Highest leverage, lowest risk.
2. **Accessibility correctness** — clickable cards whose titles are `<div>`s (no document outline), inconsistent focus-traps on overlays, notifications with no dismiss/role, sub-44px touch targets, no forced-colors fallback.
3. **Missing CD component variants** — negative (on-dark) buttons, the yellow/indigo/purple/pink badges, a canonical `.modal`/`.popover`/`.alert-banner` BEM layer.
4. **Naming divergence** — our neutral ramp is `gray-*` where CD's canonical name is `text-*`; CD's `.color--*`/`.font--*`/`.bg--secondary-*` utility shims are only partly present.

> **One real defect surfaced:** form error states are built from the primary ramp, so **errors render blue under the `.body--intranet` skin** instead of red. Fixed in Stage 1.

## The CD philosophy we are aligning to

- **Swappable brand skins.** Two ramps — `--color-primary-*` (default federal red `#d8232a`) and `--color-secondary-*` (slate) — are re-tinted at runtime by a body class (`.body--intranet` blue, `.body--freebrand` green). Everything else is static.
- **A semantic accent system with a guaranteed-AA contrast formula.** Eight fixed hues; every badge = `hue-100` bg + `hue-800` text, every notification = `hue-50` bg + `hue-700/800` text. New categorical colours ship AA-compliant *by construction*.
- **Purple `#8655F6` is reserved solely for the focus ring** — deliberately outside every brand hue so focus is unmistakable on any skin.
- **BEM everywhere** (`block__element--modifier`), with declarative utility shims (`.color--*`, `.bg--*`, `.text--*`) so raw CD/Storybook markup renders unchanged.
- **Mobile-first & WCAG-AA**: 44→48→52px touch targets stepping up by breakpoint; bold via a *font-family swap* (not just `font-weight`); `prefers-reduced-motion` respected; forced-colors survivable.
- **Ordered, layered CSS** (foundations → components → utilities) rather than one monolithic sheet.

## Gap analysis by dimension

### Foundations — Colour & skins — _strong_

**CD intent.** CD colour is built on two *swappable brand ramps* — `--color-primary-*` and `--color-secondary-*` — exposed as CSS custom properties and re-skinned at runtime by a body class: default = Swiss federal red (primary-600 #d8232a) + dark slate secondary (skins/default.postcss), `.body--intranet` = blue (skins/intranet.postcss), `.body--freebrand` = green (skins/freebrand.postcss). Everything else is *static*: one neutral ramp aliased under two names (`text-*` and `gray-*`, identical cool-gray values, tailwind.config.js:64-75,184-195) and eight fixed accent hues (blue, green, orange, yellow, red, indigo, pink, purple, teal). Accents are consumed semantically through BEM modifiers — badges pair 100-bg/800-text, notifications pair 50-bg/700-800-text (badge.postcss:23-72, notification.postcss:31-58), with `notification--alert` = red-900 bg + white for danger-to-life. Purple #8655F6 is reserved exclusively as the accessibility focus-ring colour, deliberately distinct from every brand hue, and steps down to purple-300 on dark secondary chrome (global.postcss:75-86). Semantic intent is also surfaced as utility classes: `.color--default/light/negative/link/white/black`, the full `.color--text-*`/`.color--primary-*` ramps, and `.bg--white`/`.bg--secondary-{50..900}` (colors.postcss, backgrounds.postcss).

**Our approach.** A single hand-written css/tokens.css defines the :root brand ramps (primary = federal red default; a `.body--intranet` override swaps primary→blue and secondary 400-900→blue, matching CD exactly, tokens.css:131-156), a `--color-gray-*` neutral ramp, and semantic status tokens (`--color-success/warning/error/info`, each with `-bg`/`-bg-subtle`/`-text` companions, plus `--color-alert-bg` #801519). Focus ring is `--color-focus-ring` #8655F6 and `--color-focus-ring-negative` #c4b5fd. These tokens are consumed directly in css/app.css component rules — `:focus-visible{outline:2px solid var(--color-focus-ring)}` with negative override on `.top-bar`/`.bg--secondary-6..9` chrome (app.css:89-94); `.badge--success/warning/error/info/gray/negative` and `.notification--info/success/warning/error/hint/alert` map to the status tokens (app.css:842-990). js/components.js emits `badge()`, `statusBadge()` (STATUS_VARIANT map), and `tagItem()` as plain template strings. No Tailwind/@apply. Only a partial set of CD utility classes is materialised: `.bg--white`, `.bg--secondary-{50,100,500,600,700}` (app.css:205-210) — no `.color--*` utilities, no `text-*` ramp alias.

### Foundations — Typography — _strong_

**CD intent.** CD typography is a stepped-responsive system on Noto Sans, expressed through four physically separate font files each bound to an abstract family name — Font-Regular / Font-Bold / Font-Italic / Font-Bold-Italic (css/foundations/font-face.postcss:5-35) — and selected by font-FAMILY, not by weight: the Tailwind config sets fontWeight normal=400 AND bold=400 (app/tailwind.config.js:200-203) so bold is achieved by swapping to the Font-Bold file, never by a synthetic weight. A fixed 13-step rem scale (xs 0.75rem … 9xl 5rem, tailwind.config.js:204-218) is exposed ONLY through semantic .text--xs….text--5xl classes that step up at lg/xl/3xl breakpoints — deliberately stepped, never a fluid clamp() (css/foundations/typography.postcss:18-57). Headings .h1–.h5 are thin semantic aliases over those ramps + font-bold + mb-4 (typography.postcss:106-129); supporting roles are normalized centrally: .overtitle eyebrow (100-104), .legend/figcaption caption (131-137), .text--asterisk required marker with a first-only reset (91-98), plus mark/u/del/em/strong element defaults (143-169). ### Tables — _partial_

**CD intent.** The Bund CD treats tables as semantic HTML first, styled by element (`table`, `thead`, `tbody`, `tfoot`, `caption`, `th[scope]`) rather than by wrapper classes, with a thin set of BEM modifiers layered on top: `table--compact` (dense data), `table--bare` (borderless layout table), `table--zebra` (alternating rows for wide tables), `table--caption` (reveal the otherwise visually-hidden `<caption>`), and `table--sortable` (`.table__sorter` button + `aria-sort` + JS). Structure is border-driven: a full outer border in the `text-200` grey, horizontal `border-t` row rules in `text-300`, an emphasised `border-y-2` `tfoot`, an uppercase `text--sm` `text-700` header on a `secondary-50` fill, and a `shadow-md` card lift (css/components/table.postcss:18-109). Accessibility is explicit and non-negotiable: a `<caption>` on every table (visually hidden by default, `caption-side:bottom`), `scope="col"`/`scope="row"` on all headers, per-cell text alignment via `.text-right`/`.text-center` utilities, and for sortable tables an off-screen `.sr-only` caption note plus `aria-sort`/`aria-hidden` on the sort glyphs (Table.mdx:31-128). Colour uses the `text-*` semantic scale (which equals the grey ramp) for all rules/borders, so borders share one token family with type.

**Our approach.** We render tables from a single template-string helper `table({ columns, rows, zebra, caption, showCaption, foot })` in js/components.js:137-153, emitting `<div class="table-wrapper">` › `<table class="table [table--zebra] [table--caption]">` with `<caption>`, `<thead><th scope="col">`, a `<tbody>` whose first cell per row is `<th scope="row">` (rest `<td>`), an auto empty-state row, and an optional raw-HTML `foot` slot for a `<tfoot>` row. ### Tabs & accordion — _strong_

**CD intent.** The Bund CD treats tabs and accordions as the two interchangeable ways to segment secondary content, and its guidance explicitly prefers accordions over tabs on detail pages to avoid tab overflow (Tabs.mdx line 10). Both are built on strict BEM markup (`.tab__controls`/`.tab__control`/`.tab__container`; `.accordion`/`.accordion__item`/`.accordion__button`/`.accordion__drawer`/`.accordion__content`) with a WAI-ARIA APG accessibility contract: tablist/tab/tabpanel roles with roving `tabindex`, and accordion buttons carrying `aria-expanded`/`aria-controls` plus a script that toggles `aria-hidden` and neutralises focusable elements inside a closed drawer (accordion.postcss, AccordionItem.vue, Accordion.js). Visually the tab indicator is a 3px primary underline that animates on hover/active, tabs scroll horizontally with an edge fade, and accordion drawers animate open via a `max-height 0.3s ease-out` transition (accordion.postcss lines 59-68). The federal red (`--color-primary-500 #e53940`) is the single accent for both the active-tab bar and accordion hover, and secondary-200 hairlines separate accordion rows.

**Our approach.** We reimplement both as vanilla template-string functions in js/components.js: `accordion(items,{id})` + `wireAccordion(root)` (lines 292-323) and `tabBar()`/`tabPanels()`/`wireTabs()` (lines 335-397), with hand-written CSS in css/app.css (accordion 1035-1055, tabs 1075-1093, `.tabs` 1578, print overrides 1748-1749). We adopt CD's exact BEM class names (`.tab__control`, `.tab__control--active`, `.tab__controls-container`, `.accordion__button`, `.accordion__drawer`, `.accordion__content`, `.accordion__arrow`) and CD tokens (`--color-primary-500/600`, `--color-secondary-50/200`). Tabs match CD's underline/edge-fade/scroll pattern and go beyond CD by adding a full APG keyboard model (roving tabindex, Arrow/Home/End, focus that survives re-render) that CD's own demo lacks, and by correctly pointing panel `aria-labelledby` at the tab button (CD's demo is self-referential). Accordion uses the APG-preferred `h3.accordion__heading > button > span.accordion__title` structure and toggles the drawer via the native `[hidden]` attribute (so no manual tabindex juggling is needed), and we extended it with an `.accordion__meta` cluster for format badges.

### Philosophy, accessibility, naming conventions, overall architecture — _strong_

**CD intent.** The CD Bund is a federal, multilingual, accessibility-first system whose CSS is deliberately layered: Tailwind base/components/utilities wrap a strict import cascade (skins → foundations → layouts → components → navigations → sections → print → utilities, see css/main.postcss). Design decisions live in tokens (skins/*.postcss :root vars + app/tailwind.config.js), and everything visual is expressed as BEM `block__element--modifier` classes built from those tokens via @apply. It ships three interchangeable "skins" (default federal-red, intranet-blue, freebrand) swapped at :root/body level, a full multi-hue palette (primary, secondary, and 9 named hues 50–900 plus a semantic `text-*` neutral ramp), and family-swap typography (bold is a separate font-face, not weight 700). Accessibility is a first-class contract: a purple 2px focus ring with a negative variant on dark chrome, a skip-to-content link, WCAG-AA/AAA color intent, ≥44px touch targets, `.text--asterisk` required-field convention with `speak:none`, and APG-conformant interactive components validated in Storybook + Chromatic.

**Our approach.** We reimplement CD as vanilla JS + hand-written CSS. Tokens live in css/tokens.css (:root for default skin + `.body--intranet` override), mirroring tailwind.config.js values (primary/secondary/gray ramps, --fs-*/--sp-*/--radius-*/--shadow-* scales, responsive --text-* ramps via media queries). All component CSS is one 1835-line css/app.css with plain comment banners (BASE/LAYOUT/FEDERAL SHELL/...), no CSS @layer and no file split. Components are template-string functions in js/components.js exposed via a `C` namespace; each maps props→CD BEM modifier classes (card--flat, badge--info, btn--outline, notification--error, tab__control, accordion__button, download-item, tag-item, form__group__input, select__icon, etc.), closely tracking CD block names. The app is a hash-router SPA (js/router.js) over a shared mock core (js/core.js), a federal shell (js/shell.js) and page/app modules. Accessibility is strong and in places exceeds CD: skip-to-content link, per-nav aria-labels, breadcrumb "Sie sind hier", a persistent aria-live region (#live), roving-tabindex APG tabs/menus, `@media (forced-colors: active)` icon repaint, and `markLang()` wrapping English terms in lang="en" (WCAG 3.1.2).
